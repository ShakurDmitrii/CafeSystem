# Локальная установка CafeHelp на Windows

## Требования к компьютеру

- Windows 10/11 x64;
- включённая аппаратная виртуализация;
- WSL 2;
- Docker Desktop с Linux containers;
- WebView2 Runtime;
- не менее 8 ГБ RAM, рекомендуется 16 ГБ;
- не менее 15 ГБ свободного места с учётом данных и backup.

Java, Python, Node.js, PostgreSQL и MinIO на рабочем компьютере отдельно не устанавливаются.

## Сборка release

На машине разработчика дополнительно нужны Rustup с MSVC toolchain, Node.js, Docker и Visual Studio C++ Build Tools.

```powershell
.\tools\build-windows-release.ps1 `
  -Version 0.1.1 `
  -PrinterDriverSource "C:\path\to\Thermal Printer Driver（Windows）"
```

Скрипт проверяет цифровые подписи драйверов, собирает versioned Docker images, формирует offline image-pack и создаёт NSIS installer.

## Первый запуск

1. Установить WSL 2 и Docker Desktop, если они отсутствуют; возможна перезагрузка Windows.
2. Запустить `CafeHelp Setup.exe`.
3. Открыть CafeHelp и войти как владелец.
4. Перейти в «Система» и нажать «Запустить сервисы».
5. Дождаться зелёного состояния всех компонентов.
6. При необходимости нажать «Установить драйвер» и подтвердить UAC.

## VK-бот

Образ VK-бота входит в offline installer, но контейнер по умолчанию не запускается.
Для включения Owner открывает раздел «Система», указывает числовой ID сообщества и
токен группы VK, затем сохраняет настройки. Launcher запускает профиль `vkbot` и
передаёт боту автоматически созданный внутренний токен backend. При выключении
интеграции контейнер бота останавливается, не влияя на кассу, склад и остальные сервисы.

Токен сообщества хранится только в локальном каталоге данных CafeHelp, не входит в Git
и резервную копию. Для работы бота компьютеру требуется доступ к API VK через интернет,
а в настройках сообщества должен быть включён Long Poll API.

При первом запуске launcher загружает приложенный image-pack в Docker и создаёт локальный файл секретов в каталоге данных приложения. Секреты не входят в Git и backup.

## Резервная копия

В разделе «Система» владелец нажимает «Создать резервную копию» и выбирает файл. Launcher кратко приостанавливает backend и PyModule, создаёт дампы обеих PostgreSQL-баз, копирует MinIO и модели аналитики, записывает manifest и SHA-256, проверяет читаемость архива и возобновляет сервисы.

## Обновление и откат

Перед обновлением обязательно создать backup. Обновление launcher и контейнеров не удаляет именованные Docker volumes. Для отката устанавливается предыдущий подписанный installer и возвращаются предыдущие versioned images. Автоматическое восстановление данных из backup будет добавлено отдельным этапом после проверки процедуры на чистом компьютере.
