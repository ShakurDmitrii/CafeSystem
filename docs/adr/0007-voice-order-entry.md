# ADR 0007: Голосовой набор заказа в кассе

Статус: принято, 2026-11-10.

## Контекст

Кассир собирает заказ в окне выбора блюд вручную. Нужен голосовой набор без интернета на кассе
и без «костылей»: ничего не должно попадать в чек само, а разбор фразы должен быть
воспроизводимым. Речь не свободная: кассир нажимает горячую клавишу и произносит
«<блюдо> [количество] … [N персон]», например «филадельфия кофе два эби макки три персоны».

Web Speech API в Tauri (WebView2) не работает. Проверка словаря Vosk (`vosk-model-small-ru-0.22`)
по реальному меню показала 25 отсутствующих слов (магуро, томаго, хамачи, темпура, поке, сяки…),
которые нельзя добавить без пересборки модели.

## Решение

- **Распознавание речи — faster-whisper (модель `small`, CPU, int8) в PyModule**, новый
  эндпоинт `POST /api/speech/transcribe`. Движок спрятан за интерфейсом `SpeechTranscriber`,
  модель грузится один раз при старте и далее работает без сети. Названия меню передаются
  модели подсказкой (`initial_prompt`), что повышает точность на редких словах.
- **Разбор фразы по меню — в Java, детерминированно** (`VoicePhraseParser`): нормализация
  (регистр, «ё», окончания), числительные, ключевые слова «персон», жадный поиск названия от
  самого длинного окна слов, нечёткое сравнение по словам. PyModule не знает о меню и заказах.
- **Эндпоинт кассы `POST /api/voice-orders/draft`** возвращает черновик: строки `MATCHED`
  (один уверенный кандидат), `AMBIGUOUS` (несколько близких, кассир выбирает), список
  нераспознанных слов и число персон. Частично произнесённое название («кофе» при пяти видах
  кофе) всегда `AMBIGUOUS`. Дубли меню («Суши с томаго» ×3) тоже остаются `AMBIGUOUS`.
- **Подтверждение — существующее окно выбора блюд.** Голос работает только в нём. Однозначные
  строки попадают в корзину окна, неоднозначные и нераспознанные показываются плашкой; в заказ
  позиции уходят только по кнопке «ОК», число персон применяется там же.
- **Горячая клавиша — Caps Lock в режиме переключения** (нажал — запись, нажал — отправка,
  Esc — отмена). Приложение не может запретить Windows переключать регистр, поэтому режим
  «зажал и говоришь» оставил бы Caps включённым; два нажатия возвращают его в исходное
  состояние. В текстовых полях клавиша не перехватывается. Клавиша настраивается локально
  (`localStorage`, варианты Caps Lock, F2, F4, Scroll Lock, Pause).
- Доступ: `/api/voice-orders/**` — WORKER и OWNER; роли и CSP не меняются.

## Последствия

Плюс — касса не зависит от интернета и сторонних ключей, разбор прозрачен и покрыт тестами,
распознавание можно заменить (облачный движок) без изменений в кассе. Минус — при первом старте
PyModule скачивает модель (~500 МБ), на CPU фраза распознаётся за 1–2,5 с; таблицу синонимов
блюд, команды удаления и журнал исправлений кассира оставлены на следующий этап.
