# ADR 0006: Локальная Windows-установка и резервные копии

- Статус: принято к реализации
- Дата: 2026-08-31

## Контекст

CafeHelp будет работать на одном Windows-ПК. Сейчас приложение состоит из frontend, Java backend, PyModule, двух PostgreSQL-баз и MinIO. Для печати используется отдельный подписанный драйвер Rongta. Пользователю нужен привычный запуск через EXE и создание резервной копии непосредственно из приложения.

## Решение

### Формат поставки

Поставлять CafeHelp как Tauri 2 Windows application в NSIS installer, который устанавливает:

1. launcher CafeHelp;
2. локальный набор контейнеров и конфигурацию приложения;
3. ярлык запуска;
4. опциональный установщик драйвера термопринтера;
5. средства создания и восстановления резервных копий.

Tauri launcher использует существующий React frontend, запускает локальные сервисы, проверяет их healthcheck и открывает интерфейс CafeHelp в системном WebView2. Offline Docker image-pack входит в installer как ресурс, но сервисы и пользовательские данные работают отдельно от процесса launcher и не перезаписываются при его обновлении.

### Драйвер термопринтера

В дистрибутиве допускается хранить два оригинальных подписанных установщика Rongta:

- `RongTaDriverInstall V2.65.exe` для обычной x64 Windows;
- `DriverInstallArm64_V1.03.exe` для Windows ARM64.

Installer определяет архитектуру системы и предлагает отдельный явный пункт «Установить драйвер принтера». Драйвер запускается с повышением прав только после подтверждения пользователя. Повторная установка при каждом запуске CafeHelp запрещена.

Перед публикацией дистрибутива необходимо подтвердить право на распространение файлов драйвера. В Git-репозиторий бинарные установщики не добавляются; они подключаются к release-сборке из отдельного каталога артефактов.

### Резервная копия

В разделе владельца появляется действие «Создать резервную копию». Launcher открывает стандартный диалог выбора файла и формирует единый архив `.cafehelp-backup`, содержащий:

- `main.dump` — custom-format dump основной PostgreSQL-базы;
- `tax.dump` — custom-format dump налоговой PostgreSQL-базы;
- каталог или архив объектов MinIO;
- модели PyModule;
- `manifest.json` с версией CafeHelp, версиями схем, временем создания и составом архива;
- `checksums.sha256` для проверки целостности.

Копия создаётся во временном каталоге. На время согласованного снимка launcher приостанавливает backend и PyModule, а после операции обязательно возобновляет их, включая сценарий ошибки. Архив полностью читается для проверки CRC и только после успеха переносится в выбранное место. Пароли базы не записываются в архив или журналы.

### Восстановление

Восстановление выполняется отдельным мастером launcher до запуска рабочих сервисов. Перед восстановлением текущие данные автоматически сохраняются в аварийную копию. Архив проверяется по manifest и SHA-256. Восстановление поверх работающей системы запрещено.

## Права доступа и безопасность

- Создание резервной копии доступно только пользователю с ролью `OWNER`.
- Восстановление требует повторного подтверждения и локального доступа к Windows-ПК.
- Секреты берутся из локального защищённого хранилища launcher и не передаются frontend.
- В журнал записываются результат, длительность и путь без чувствительных данных.

## Эксплуатация

- Ручная копия создаётся кнопкой в интерфейсе.
- Дополнительно launcher создаёт автоматическую ежедневную копию с ограничением количества хранимых версий.
- После создания выполняется тест чтения архива и проверка checksums.
- Не реже одного раза после крупных обновлений проводится тестовое восстановление.

## Альтернативы

### Один полностью автономный portable EXE

Отклонено: PostgreSQL, MinIO, Java и Python требуют отдельных процессов и постоянных каталогов данных. Упаковка всего в один запускаемый файл усложняет обновление, диагностику и сохранность данных.

### Только дамп основной базы

Отклонено как полноценная резервная копия: будут потеряны налоговые данные и загруженные изображения. Отдельный экспорт только основной базы может остаться как дополнительная диагностическая функция.

### Кнопка, запускающая `docker exec` прямо из браузера

Отклонено: браузер не должен иметь доступ к Docker и системным командам. Привилегированные операции выполняет только локальный launcher.

## Последствия

Плюсы:

- привычная установка и запуск на одном ПК;
- корректная установка драйвера;
- полная переносимая резервная копия;
- безопасное восстановление и обновление.

Минусы:

- дистрибутив будет крупнее из-за локальных сервисов и offline-образов;
- потребуется отдельная Windows-сборка launcher и installer;
- необходимо сопровождать процедуру обновления контейнеров и формата backup.

## Этапы реализации

1. Собрать Tauri launcher, запуск и healthcheck локальных сервисов.
2. Добавить release-каталог драйверов и installer hook с выбором архитектуры.
3. Реализовать команды `backup` и `restore` launcher.
4. Добавить OWNER-only страницу «Система» и связь с launcher.
5. Добавить автоматические копии, ротацию и проверку восстановления.
6. Собрать и проверить offline installer на чистой Windows-машине.
