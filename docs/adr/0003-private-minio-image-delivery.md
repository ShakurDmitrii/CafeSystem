# ADR-0003: Приватное хранение и контролируемая выдача изображений

- **Статус:** принято
- **Дата:** 29 августа 2026 года
- **Область:** загрузка изображений, MinIO, каталог продуктов и блюд

## Требования и ограничения

Пользовательские файлы нельзя считать изображениями только по имени или заголовку
`Content-Type`. Бакет не должен становиться публичным ради отображения фотографий в кассе.
При замене изображения и отмене создания карточки неиспользуемые объекты должны удаляться,
но очистка не должна удалить файл между загрузкой и сохранением сущности.

## Решение

1. Backend принимает только JPEG и PNG размером до 5 МБ, сверяет MIME с сигнатурой,
   декодирует изображение и ограничивает ширину, высоту и общее число пикселей.
2. Исходное имя не используется. Ключ имеет вид
   `{products|dishes|dish-sets|misc}/{uuid}.{jpg|png}`.
3. `POST /api/v1/files/images` доступен только роли `OWNER`. Старый
   `POST /api/files/upload-image` временно оставлен как совместимый alias.
4. Новые ссылки ведут на `GET /api/v1/files/images/{folder}/{filename}`. Маршрут разрешает
   только серверный формат ключа, отдаёт фиксированный MIME, `nosniff` и длительный cache.
   Бакет MinIO и операция перечисления объектов остаются приватными.
5. Объекты без ссылки из `sales.product`, `sales.dish` или `sales.dish_set` удаляются после
   24-часового защитного окна. Очистка ограничена пачкой и запускается раз в шесть часов.
6. Ошибки клиента возвращают `400` или `413`, отсутствие объекта — `404`, недоступность
   MinIO — `503` с `Retry-After`. Внешний ответ не содержит адрес или детали MinIO.

## Рассмотренные варианты

### Публичный bucket policy

Отклонён: он расширяет поверхность доступа, допускает обход backend-проверок и усложняет
отзыв публикации. Для текущего объёма проксирование файлов до 5 МБ приемлемо.

### Presigned URL

Отложен. Он уменьшит нагрузку на backend, но требует корректного внешнего адреса MinIO,
ограниченного TTL и обновления URL на клиенте. Это разумная оптимизация после измерений.

### Немедленное удаление при закрытии формы

Недостаточно надёжно: браузер может закрыться или потерять сеть. Фоновая очистка покрывает
такие случаи, а защитное окно не конфликтует с сохранением карточки.

## Развёртывание и миграция

Перед `docker compose up` задать `MINIO_ROOT_USER` и длинный `MINIO_ROOT_PASSWORD`, а также
JWT/internal token. Публичный адрес backend задаётся `PUBLIC_API_BASE_URL`. MinIO API и
консоль публикуются только на `127.0.0.1`; для удалённого администрирования использовать
защищённый туннель или reverse proxy с отдельной аутентификацией.

Старые прямые URL в БД не переписываются и продолжают работать в прежней среде. Новые
загрузки получают backend URL. После проверки всех рабочих мест прямые URL можно мигрировать
по ключу объекта и затем снять старую публичную policy бакета, если она создавалась вручную.

## Откат

Откат backend не требует изменения объектов или БД. До отката сохранить старую доступность
MinIO для прежних прямых ссылок. Фоновую очистку можно остановить через
`STORAGE_MINIO_CLEANUP_ENABLED=false`; удалённые объекты восстанавливаются только из backup,
поэтому backup бакета должен быть проверен до уменьшения защитного окна.
