# CafeSystem UI: контекст и прогресс

Этот файл хранит решения по редизайну между рабочими сессиями. Перед продолжением
нужно проверить `git status`, прочитать этот файл и не перезаписывать чужие изменения.

## Цель

Сделать интерфейс CafeSystem понятным для владельца и сотрудников кафе, не меняя
существующую бизнес-логику и API. Каждую страницу сначала аккуратно декомпозируем,
затем обновляем визуально и проверяем на десктопе, планшете и телефоне.

## Постоянные правила

- Сохранять текущие маршруты, роли `OWNER` / `WORKER` и поведение API.
- Не переписывать рабочую логику без необходимости; выносить её небольшими шагами.
- Поддерживать ширину от 320 px, safe area и удобные зоны нажатия не меньше 44 px.
- Использовать семантические элементы, подписи полей, видимый `:focus-visible`,
  понятные ошибки и `aria-live` для асинхронных сообщений.
- Учитывать `prefers-reduced-motion`; не использовать `transition: all`.
- Визуальная основа: глубокий зелёный, белый и спокойные мятные оттенки; интерфейс
  напоминает рабочую смену кафе, а не универсальный административный шаблон.
- Шрифты: Bahnschrift для акцентных заголовков, Aptos для текста, Cascadia Mono
  для числовых и служебных данных.
- Не трогать несвязанные изменения в dirty worktree.

## Известный технический долг

- Проект использует старый `react-scripts@5`; `npm test` конфликтует с текущим
  разрешением `react-router-dom@7`, хотя production build проходит.
- В проекте есть существующие ESLint warnings вне уже обновлённых экранов.
- `npm ci` сообщает о 56 уязвимостях зависимостей, включая 2 critical; автоматический
  `npm audit fix` не запускался, чтобы не вносить ломающие обновления.
- В маршрутах есть историческое написание `/consigment`; не менять без отдельной
  проверки ссылок и backend-контрактов.
